## 三、本轮改造清单（逐项可验证）

### P0-1 断言强度：从「只比标题」到「断言业务结果」

**改造前**：6 条用例只有 1 处 `assertEqual`（在 `check_title` 内部），
于是上传失败、查询 0 命中、报送被拒、接口 500 全都判绿 —— **假绿**。

**改造后**三层断言：
```
① 业务结果断言（最重要）
     test_4  上传后 wait_material_count(at_least=before+1)  行数真的 +1
     test_6  报送后 wait_status_changed(before)             状态真的变了
     test_5  查询后列表正常渲染
② 结构断言
     test_3  query_form_ready()  查询区控件齐全（缺一个就说明前端改版）
③ 守卫断言
     全部    check_title() + check_no_console_error()  页面没崩、无 JS 报错
```

验证：
```bash
grep -c "def test_" TestSuites/testLogin.py                    # 6
grep -c "assert\|check_\|wait_material_count\|wait_status" TestSuites/testLogin.py
python tests/run_unit_tests.py tests.test_test_login_suite     # 含防回退门禁
```

### P0-2 用例独立性：任意用例可单独运行

**改造前**：只能从 `test_1` 顺序跑（共享浏览器 + 数字前缀固定顺序）。

**改造后**：三级前置自愈，**幂等**（已在目标页时立即返回，顺序跑零开销）：
```bash
python run.py --cases test_5keyword   # 单独跑第 5 条，现在可以了
```

### P0-3 定位去脆弱化

| 条目 | 改造前 | 改造后 |
|---|---|---|
| `submission` | `td[8]/button[3]` 长链路 | 按可见文字「报 送」锚定 |
| `first_trial` | `/html/body/div[4]/...` 绝对路径 | 按「初审」文字向上找表单项 |
| `person_of_first_instance` | **下拉第 8 项**（会静默选错人） | `first_trial_person(姓名)` 按姓名定位 |

```bash
python -m Common.locator_policy    # ABSOLUTE 0 条（红线）；flawed 10
```

★ "写死下拉序号"是最危险的一类——选错人不报错、用例照样绿。

### P0-4 质量门禁真实生效

| 门禁 | 改造前 | 改造后 |
|---|---|---|
| flake8 | `\|\| true` 静默跳过 | **缺失即 exit 2**；实测 0 问题 |
| 覆盖率 | 无 | `fail_under=82`，实测 87% |
| 类型检查 | 无 | mypy stage（渐进式，先覆盖 Common/） |
| pre-commit | 无 | 4 类钩子（含私钥检测、定位门禁、业务数据门禁） |

### P1-5 稳定性机制默认生效

**改造前**：`safe_click`/`safe_type` 写了但用例层 0 次调用 → 等于没有。
**改造后**：`click()`/`type()` **内置重试**，且区分错误类型：

```
瞬时错误（元素过期 / 等待超时 / 被遮挡）-> 重试（默认 2 次）
确定性错误（元素不存在 / 参数错 / 断言失败）-> 立即失败，不浪费重试
截图只在最终失败时拍 1 张（重试期间不刷屏）
```
另外 12 处 `my_sleep(2/3/5)` 全部换成条件等待（`wait_title`/`wait_text`/
`wait_loading_gone`/`wait_material_count`/`wait_status_changed`）——
**更快**（对了就返回）且**更稳**（不再靠拍脑袋的秒数）。

### P1-6 测试分层：补接口层

新增 `Common/apiClient.py`（会话保持 / 统一日志 / 可读错误）
+ `TestSuites/testApiSmoke.py`（样例模板，未配 `[api] base_url` 时自动跳过）。

### P1-7 可观测性：失败归因 + 通过率趋势

```
Common/failureClassifier.py   7 类归因：定位/环境/配置/业务/数据/超时/未归类
                              每类附「下一步找谁」的建议
Common/trend.py               Report/history.jsonl + 连续下滑告警
```

## 四、仍然存在的边界（不吹）

| 项 | 现状 | 说明 |
|---|---|---|
| 接口层用例 | **只有骨架** | 需要各系统按真实接口填充；框架与假响应测试已就绪 |
| 类型标注 | 渐进式 | 14829 行只有少量 `->`；mypy 先覆盖 `Common/`，全量标注是长期工作 |
| 定位脆弱度 | 10 条 INDEXED/DEEP_INDEX | 已无绝对路径；剩余需逐条按可见文字替换 |
| loginPage/genericPage 覆盖率 | 51% / 52% | 强依赖真实页面，单测覆盖天然有限；已如实记录在 pyproject 注释里 |
| pytest / Allure | 未迁移 | unittest 体系已补齐能力（fixture 式前置自愈、覆盖率、趋势）；迁移是选型偏好，非必需 |
| 真实环境验证 | **未做** | 本次改造全部为本机静态与单测验证；业务断言（行数 +1 / 状态变化）需在真实环境跑一轮确认 |
| Grid / 多浏览器矩阵 | 未实测 | 代码支持，未在真实网格验证 |

> ⚠️ 最重要的一条：**业务断言必须在真实环境跑一轮**。
> `wait_material_count` / `wait_status_changed` / `query_form_ready` 依赖
> `elementPage` 里新增的观察点定位（`material_rows` / `first_row_status` /
> `total_count`）与真实 DOM 的匹配。这三条定位是按通用结构写的
> （`//table//tbody/tr`、`td[last()]`、含"共...条"的文字），
> 大概率可用，但**必须验证**。
